# CW-122B1 — Codex mock qualification

**Status:** mock adapter qualification passed; live execution remains **NO-GO**.

CW-122B1 qualifies the installed Codex CLI and Context-Watcher's authenticated Responses path without contacting a model provider. It does not qualify coding-agent product value or authorize provider spend.

## Run contract

`benchmark/cw122b1/run_mock_campaign.py` runs the ignored Rust integration test through the real `codex` executable. It must be run from a Git checkout because the runner records the verified output of `git rev-parse HEAD`; source archives and caller-supplied commit overrides are unsupported. It requires an empty evidence directory outside the checkout with mode `0700`, records the Codex version and frozen CW-122A digest, and launches Cargo with `--offline --locked` under the CW-122A minimal environment allowlist. There is no live mode; `--live` is rejected.

Each of 12 counterbalanced attempts gets a fresh workspace, `HOME`, `CODEX_HOME`, temporary directory, session, control credential and store. The initial and resumed invocations use the same task prompts, Codex version, model label and configuration. The Codex child gets a dummy API key only to authenticate to the loopback proxy. The shell tool environment is separately filtered; a real Codex tool call checked for `OPENAI_API_KEY`, `CW_CONTROL_TOKEN`, and proxy variables and observed none. Proxy credentials are removed before provider egress.

The mock endpoint is an in-process loopback server. Codex is configured to use only `http://127.0.0.1:<port>/openai/v1`; user configuration is ignored, `workspace-write` tool networking is explicitly disabled, Codex analytics and the built-in metrics exporter are disabled, and outbound request metadata is checked for `analytics_enabled: false`. The [Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-advanced) documents these analytics and sandbox settings. The Context-Watcher HTTP client has redirects disabled; an integration test confirms a mock 307 is returned without contacting a loopback tripwire. No provider fallback is configured.

Each run has a 600-second total deadline across both Codex invocations; the campaign has a 7,200-second deadline. The fixed 12 attempts and per-session SpendGuard limit of 30 admitted requests are backed by a shared, atomic 360-request campaign cap enforced before dispatch. The Linux runner discovers descendant process groups and verifies they are gone after timeout or cancellation. The Rust attempt guard writes observed ingress, egress, mock requests, and responses to a private `failed/` directory if an assertion or panic interrupts an attempt. These guards are covered by offline regressions. There are no automatic retries of campaign attempts.

## Mock campaign result

The hardened final host run at commit `9525252be75be1d1e04825b5fc52404b10b316c8` used `codex-cli 0.166.0` and passed all 12 attempts (six pairs across F1 and F2, both arm orders), with 48 local mock requests. Each attempt made four requests. All 12 independent fixture oracles passed. M1 had no applied pruning. Every M2 attempt recorded two verified applications to the completed historical probe output in the resumed and following request; original transcripts retained the unmodified output. The [sanitized machine-readable aggregate](../benchmark/cw122b1/mock-aggregate.json) includes request and response hashes, pair results, treatment counts, and links to the private manifest by hash.

For every request, the test compared the complete egress JSON with the exact expected payload, checked persisted egress against the mock's received bytes, reconciled provider-reported mock usage with the turn ledger, and required matching mutation IDs. The first probe tool result was complete and consumed in a subsequent assistant turn before M2 committed its pruning rule. The final implementation prompt contains no repeated task constraints. All 48 mock responses included usage records: 6,768 input tokens, 672 output tokens, and 768 cached tokens, all synthetic. There were zero observed tool/provider errors; retry count is `NOT_AVAILABLE` because Codex does not expose a reliable retry counter in this path.

All campaign artifact fields ending in `_sha256` and transcript hash arrays use the SHA-256 algorithm. The Rust implementation is checked against the standard `abc` known vector, and the manifest records `hash_algorithm: SHA-256`. BLAKE3 remains used by unrelated existing immutability tests, but its values are not labeled or published as SHA-256 evidence.

Observed request sampling fields matched across all attempts: temperature and top-p were unset, and reasoning summary was `auto`. No Codex CLI warning events were recorded in the final campaign. The `gpt-4o-mini` value is only a synthetic request label used by the local SpendGuard accounting; the campaign does not qualify a production model selection.

The run's provider call count and provider spend were both zero. Mock usage is synthetic. Cache hits, cache fairness, real token economics, provider latency, inference behavior and product value are **NOT_EVALUATED**. Both arms passing the scripted oracle cannot establish a correctness advantage. The mock's command responses include frozen fixture repairs, so this test validates CLI routing, resume lifecycle, treatment delivery and evidence accounting—not autonomous coding quality.
